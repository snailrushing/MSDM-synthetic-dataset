# Multi-state deck motion synthetic dataset for aircraft autonomous landing on ships

This repository contains the generator scripts, documentation, raw dataset and evaluation results of representative deep-learning mathods for a **multi-state** **deck-motion synthetic dataset** intended for deck motion prediction in aircraft autonomous landing on ship. The data are produced by a potential-flow time-domain ship-motion simulation in the open-source [Marine Systems Simulator (MSS)](https://github.com/cybergalactic/MSS) toolbox developed at the Norwegian University of Science and Technology (NTNU).

Two generators are provided:

| Script                                          | Purpose                                                                   | Output size                            |
| ----------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------- |
| `SIMtankerDeckMotion_AllStates.m`             | Full training/evaluation dataset across 3 sea states × 8 wave directions | 2,400 CSV files (train/val/test split) |
| `SIMtankerDeckMotion_AblationWaveDirection.m` | Held-out wave-direction ablation set (directions offset by 22.5°)        | 24 CSV files                           |

Both scripts produce the same per-sample signal columns; they differ only in the set of wave directions, the number of random realizations.

---

## 1. Motivation and approach

In aircraft autonomous landing, the future motion states of the ideal landing point is crucial for safety. The onboard pose sensing system need to give accurate deck motion prediction in advance. As a typical time-serie predicition problem, data-driven  methods are now dominant. To train and evaluate the performance of predictors, large amount of deck motion data is required. However, real, precise and continuously measured deck-motion records are expensive to collect. Public synthetic deck motion dataset designed for autonomous landing is absent.  Based on this consideration, we build this multi-state deck motion synthetic dataset, in which different sea stats and wave directions are covered.  Different from existing datasets focusing on ship trajectories, the proposed dataset only involve the heaving, heaving velocity, roll, and pitch (i.e. 4 DoF deck motion ), which are most vital to autonomous landing. To guarantee **controllability, reproducibility, and complete ground truth**, the dataset is generated by numerical simulation:

- **Vessel dynamics** — 6-DOF rigid-body motion under first-order wave loads, solved in the time domain.
- **Hydrodynamics** — frequency-domain potential-flow data (added mass, potential damping, and first-order wave-excitation RAOs) computed with WAMIT, converted to constant time-domain matrices by the power-equivalent method.
- **Wave environment** — long-crested irregular seas described by a JONSWAP spectrum, synthesized as a superposition of many regular wave components with random phases.
- **Ground-truth velocity** — the deck-point velocity is obtained **analytically** from the rigid-body velocity field (via the lever-arm transform), not by numerical differentiation of the position, so the velocity label is free of the phase lag and noise amplification that differencing would introduce.

## 2. Vessel model

The simulated vessel is the MSS `tanker` (WAMIT data in `tanker.mat`). Its main particulars are:

| Quantity                                        | Symbol     | Value  | Unit |
| ----------------------------------------------- | ---------- | ------ | ---- |
| Length between perpendiculars                   | $L_{pp}$ | 246    | m    |
| Beam                                            | $B$      | 46     | m    |
| Draft                                           | $T$      | 10     | m    |
| Displaced volume                                | $\nabla$ | 92,312 | m³  |
| Block coefficient                               | $C_B$    | 0.816  | —   |
| Displacement mass                               | $m$      | 94,620 | t    |
| Longitudinal center of gravity (fwd of midship) | $x_g$    | 3.93   | m    |
| Transverse center of gravity                    | $y_g$    | 0      | m    |
| Vertical center of gravity (above waterline)    | $z_g$    | 2.5    | m    |

The vessel is modeled with a 6-DOF rigid-body equation of motion about the body coordinate origin (CO). In the compact vector form used by the simulation:

$$
M\,\dot\nu_r + C(\nu_r)\,\nu_r + D(\nu_r)\,\nu_r + G\,\eta = \tau_{\text{ctrl}} + \tau_{\text{wave}}
$$

with $\eta=[x,y,z,\phi,\theta,\psi]^\top$ (position and Euler angles) and $\nu=[u,v,w,p,q,r]^\top$ (body-fixed linear and angular velocities). $M=M_{RB}+A_{eq}$ is the rigid-body-plus-added-mass inertia matrix,
$C(\cdot)$, $D(\cdot)$, and $G$ are the Coriolis–centripetal, damping, and restoring matrices, $\tau_{\text{ctrl}}$ is the control force, and $\tau_{\text{wave}}$ is the first-order wave-excitation force.

The frequency-dependent added mass $A(\omega)$ and potential damping $B(\omega)$ are reduced to constant matrices using the power-equivalent method with the normalized wave spectrum $S_N(\omega)=S(\omega)/m_0$:

$$
A_{eq}=\int_0^{\infty} A(\omega)\,S_N(\omega)\,d\omega,\qquad
B_{eq}=\int_0^{\infty} B(\omega)\,S_N(\omega)\,d\omega .
$$

## 3. Wave environment

Irregular seas are generated from a **JONSWAP** spectrum with peakedness factor $\gamma=3.3$, in the **long-crested (unidirectional)** configuration (`spreadingFlag = 0`). Three sea states are simulated:

| Sea state | $H_s$ (m) | $\omega_0$ (rad/s) |
| --------- | ----------- | -------------------- |
| SS4       | 2           | 0.79                 |
| SS5       | 3           | 0.63                 |
| SS6       | 5           | 0.50                 |

The wave excitation is synthesized by superposing regular wave components whose amplitudes follow the spectrum and whose phases are drawn uniformly from $[0,2\pi)$. Each component is passed through the first-order wave-force RAO to obtain the corresponding force time series; a distinct random seed therefore yields a statistically independent realization of the same sea state.

---

## 4. Deck-point motion transform

The ship dynamics provide the 6-DOF motion of the origin CO. The motion of an arbitrary point $P$ on the deck, located at lever arm $r_p$ from CO, is obtained by a rigid-body transform. Position and velocity of $P$ in the NED frame are:

$$
p_{NED}=\eta_{1:3}+R(\phi,\theta,\psi)\,r_p
$$

$$
\dot p_{NED}=R\left[\nu_{1:3}+\omega\times r_p\right],
\qquad \omega=[p,q,r]^\top
$$

where $R$ is the body-to-NED rotation matrix. The deck point used here is at the **stern, on the centerline, 5 m above the **still-water line**: $r_p=[-123,\,0,\,-5]^\top$ m (FSD convention). The 123 m
longitudinal lever arm means the point's vertical motion is dominated by pitch — the "long-lever amplification" characteristic of deck motion, which is one of the phenomena this dataset is designed to capture. The **heave velocity is the analytic** value $\dot p_{NED,z}$, not a numerical derivative.**

## 5. Simulation configuration

| Parameter                | Value                                                            |
| ------------------------ | ---------------------------------------------------------------- |
| Simulation length        | 300 s                                                            |
| Integration              | 4th-order Runge–Kutta (RK4),$h=0.04$ s → **25 Hz**     |
| Wave-force update period | 0.1 s                                                            |
| Wave components          | 100 frequency intervals                                          |
| Heading control          | PID heading autopilot, reference$\psi=0^\circ$ (fixed heading) |
| Forward speed            | constant surge thrust 2.4×10⁶ N, ≈ 30 kn (15.43 m/s)          |
| Current                  | none ($V_c=0$)                                                 |

Each realization yields $300 / 0.04 + 1 = 7501$ time samples.

## 6. Dataset 1 — `SIMtankerDeckMotion_AllStates.m`

### 6.1 Scope

The full dataset spans **3 sea states × 8 wave directions = 24 operating conditions**. The wave directions are

$$
0^\circ,\,45^\circ,\,90^\circ,\,135^\circ,\,180^\circ,\,225^\circ,\,270^\circ,\,315^\circ
$$

where $0^\circ$ denotes following seas and $180^\circ$ head seas (relative to the fixed vessel heading). Each condition is simulated **100 times** with independent random wave phases, giving **24 × 100 = 2,400** CSV files.

### 6.2 Train / validation / test split

Within each condition, the 100 independent realizations are split **contiguously
by realization index**:

| Split | Realization indices | Files per condition | Total files      |
| ----- | ------------------- | ------------------- | ---------------- |
| train | 1–70               | 70                  | 24 × 70 = 1,680 |
| val   | 71–85              | 15                  | 24 × 15 = 360   |
| test  | 86–100             | 15                  | 24 × 15 = 360   |

Because every realization is an i.i.d. draw of the random phases, a fixed
contiguous assignment is a valid random split with **no temporal leakage**
between train and test.

### 6.3 Output layout and naming

```
generated_data_all_states/
├── train/   tanker_seastate_A_angle_B_C.csv   (1,680 files)
├── val/     tanker_seastate_A_angle_B_C.csv     (360 files)
└── test/    tanker_seastate_A_angle_B_C.csv     (360 files)
```

- `A` — sea-state level (`4`, `5`, or `6`)
- `B` — wave direction in degrees (`0`, `45`, …, `315`)
- `C` — realization index (`1`…`100`)

## 7. Dataset 2 — `SIMtankerDeckMotion_AblationWaveDirection.m`

### 7.1 Scope

This is an **ablation set for wave-direction generalization**: it holds out the directions that lie exactly **between** the training directions, offset by
22.5°:

$$
22.5^\circ,\,67.5^\circ,\,112.5^\circ,\,157.5^\circ,\,202.5^\circ,\,247.5^\circ,\,292.5^\circ,\,337.5^\circ
$$

Together with the 3 sea states this gives **3 × 8 = 24** held-out conditions. Each condition is simulated **once** (a single random wave-phase realization), producing **24** CSV files. This set is intended to test whether a model trained on the `AllStates` directions can generalize to *unseen* wave directions — an ablation over the directional coverage of the training data.

### 7.2 Output layout and naming

```
generated_data_ablation_wave_direction/
└── tanker_seastate_A_angle_B.csv   (24 files)
```

- `A` — sea-state level (`4`, `5`, or `6`)
- `B` — wave direction in degrees (`22.5`, `67.5`, …, `337.5`)

---

## 8. CSV format

Every CSV file has one header line followed by 7,501 rows. Columns, in order:

| # | Column             | Unit | Description                                                |
| - | ------------------ | ---- | ---------------------------------------------------------- |
| 1 | `time_s`         | s    | Simulation time                                            |
| 2 | `heave_m`        | m    | Deck-point heave displacement,**positive up**        |
| 3 | `heave_vel_mps`  | m/s  | Deck-point heave velocity,**positive up** (analytic) |
| 4 | `roll_deg`       | deg  | Roll angle$\phi$                                         |
| 5 | `pitch_deg`      | deg  | Pitch angle$\theta$                                      |
| 6 | `sea_state_norm` | —   | Sea-state level / 15 (SS4→0.2667, SS5→0.3333, SS6→0.4)  |
| 7 | `sin_beta_wave`  | —   | $\sin\beta$, $\beta$ = wave direction (rad)            |
| 8 | `cos_beta_wave`  | —   | $\cos\beta$, $\beta$ = wave direction (rad)            |

The last three columns are constant within a file and encode the operating condition as continuous inputs, so a model can condition on sea state and wave direction. `heave_m`, `heave_vel_mps`, `roll_deg`, `pitch_deg` are the raw simulation truth signals.

## 9. Regenerating the dataset

Run the scripts from MATLAB (R2021b or later) with the MSS toolbox on the path.

```matlab
% Full dataset (defaults: SS4/5/6, 0:45:315 deg, 100 runs/condition)
SIMtankerDeckMotion_AllStates

% Ablation set (defaults: SS4/5/6, 22.5:45:337.5 deg, 1 run/condition)
SIMtankerDeckMotion_AblationWaveDirection
```

Both accept optional name/value overrides, e.g. for a quick smoke test:

```matlab
SIMtankerDeckMotion_AllStates('numRuns', 2, 'outputDir', 'tmp_smoke');
SIMtankerDeckMotion_AblationWaveDirection('outputDir', 'tmp_smoke_ablation');
```

| Option               | `AllStates` default         | `AblationWaveDirection` default          |
| -------------------- | ----------------------------- | ------------------------------------------ |
| `'seaStates'`      | `[4 5 6]`                   | `[4 5 6]`                                |
| `'Hs'`             | `[2 3 5]`                   | `[2 3 5]`                                |
| `'w0'`             | `[0.79 0.63 0.5]`           | `[0.79 0.63 0.5]`                        |
| `'waveDirections'` | `0:45:315`                  | `22.5:45:337.5`                          |
| `'numRuns'`        | `100`                       | —                                         |
| `'outputDir'`      | `generated_data_all_states` | `generated_data_ablation_wave_direction` |
| `'seedStart'`      | `1`                         | `1`                                      |
| `'splitCounts'`    | `[70 15 15]`                | —                                         |
